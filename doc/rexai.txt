1. INTRODUCTION                                           *rexai-introduction*

rexai.nvim shows the AI coding agents running in Rex as a Dashboard in
Neovim. It lists each Agent block under its Session with its Agent status,
takes you to one with a key and starts new agent Sessions. It shows only
what Rex reports. It knows nothing about what started the agents.

Requirements: Neovim 0.11 or newer; Rex, with its `rex` command on PATH (or
set `rex_bin`); `git`, optional. The Dashboard never starts a Rex server:
its calls carry `--autostart=false`.

==============================================================================
2. INSTALL                                                     *rexai-install*

With lazy.nvim: >lua
    {
        'vieitesss/rexai.nvim',
        cmd = 'Rexai',
        opts = {},
    }
<
Or call setup() yourself: >lua
    require('rexai').setup()
<
Only |:Rexai| and the session autocmd are defined at startup. The Dashboard
code loads when the command runs or a session loads. setup() is optional:
without it the defaults apply.

==============================================================================
3. USAGE                                                         *rexai-usage*

                                                                    *:Rexai*
:Rexai          Show the Dashboard in the current window.

Sourcing a session that holds the Dashboard, as |:restart| does, gives the
Dashboard back in every window that showed it, with its keys and its refresh.

The Dashboard is a buffer in the current window. `q` (see |rexai-keys|)
gives that window back its previous buffer. It lists the Sessions that hold
Agent blocks. The Home session is always listed and marked (home). A Session
header shows the highest Agent status among its rows. Rows are sorted by
Agent status, highest first. When git works in a row's directory, a git
column shows "repo · branch ↑ahead ↓behind ●changed", leaving out zero
counts. A row with no git result leaves that column blank.

The Dashboard polls Rex every `refresh_ms` (see |rexai-config|) while a
window shows it and Neovim has focus. It also asks when it opens, on `r`,
and when Neovim gains focus. When Rex cannot be read, it shows "Rex
unreadable:" with the reason and retries after 5 seconds.

Sample, with invented names: >
    ! api
      ! needs input  add the migration      claude-code 4d5e  1m
      x error        fix the failing test   pi 7a8b           4m
      + done         write the parser docs  claude-code 0b1c  14m
      ? unreported   look at the logs       opencode 6b7c
      - idle         waiting for review     pi 9e0f           2h
      . exited 1     port the old script    pi 2b3c           9m

    * my-project (home)
      * working      refactor the parser    pi 1b2c           45s
<
Agent statuses and their default glyphs:

    needs input  !  Rex reports the Block as blocked.
    error        x  Rex reports an error.
    done         +  Rex reports the agent is done.
    working      *  Rex reports the agent is working.
    unreported   ?  The agent is running but reports no status.
    idle         -  Rex reports the agent is idle.
    exited       .  The agent has ended while its Block stays open. The
                    row shows the exit code.

4. KEYS                                                           *rexai-keys*

These keys work in the Dashboard buffer, in normal mode. The Dashboard maps
only keys that edit text, which a read-only buffer never needs, so Vim keeps
its own meaning for d, e, n, N and ?.

    <CR>  Go to the Agent block under the cursor, or to the Session of a
          header. Rex changes the view itself.
    K     Open a float with what is known about the Agent block, and the
          last lines of its screen. Press K again to enter the float. q
          or <Esc> close it. The float closes when the cursor moves.
    o     Hand the row under the cursor to the review hook. See
          |rexai-hooks|.
    r     Ask Rex for a snapshot now.
    x     Show or hide the Exited rows. The choice lasts until the
          Dashboard buffer is wiped. It is not a config option.
    a     Add a Window to the Session under the cursor. See
          |rexai-starting|.
    A     Start a Session for a directory you name. See |rexai-starting|.
    q     Close the Dashboard. Shows the buffer that was in the window
          before. Closes the window when that buffer is gone and other
          windows exist.
    g?    Open a float with one line per Dashboard key, the key and what
          it does. The float is the one K opens: it closes when the cursor
          moves, on entering Insert mode, or when the buffer is left.

5. CONFIGURATION                                                *rexai-config*

setup() merges your options over the defaults. A list replaces the default
list; it does not add to it. A table such as `glyphs` keeps the entries you
do not set. Without setup(), the defaults apply.

    refresh_ms      integer, default 1000. How often the Dashboard asks
                    Rex for a snapshot.
    git_refresh_ms  integer, default 5000. How old a git result may be
                    before it is asked again.
    show_exited     boolean, default true. The starting value of the `x`
                    toggle: whether Exited rows are listed.
    title_width     integer, default 40. The widest title, in display
                    cells, the ellipsis included.
    rex_bin         string, default 'rex'. The rex executable the Dashboard
                    and |:checkhealth| run.
    peek_lines      integer, default 20. How many lines from the end of a
                    Block the K float keeps.
    focus_new       boolean, default true. Whether `a` and `A` select the
                    Window or Session they made. false leaves the view
                    where it is.
    session_name    function or nil, default nil. Names a new Session from
                    its directory. See |rexai-hooks|.
    glyphs          table. One single-width character per Agent status.
                    See the default below.
    resolve_path    function or nil, default nil. Gives the directory a row
                    stands for. See |rexai-hooks|.
    review          function or nil, default nil. What `o` calls with the
                    context of a row. See |rexai-hooks|.
    agents.apps     list, default { 'claude-code', 'pi' }. `app` names in
                    Rex program status records that make a Block an Agent
                    block.
    agents.commands list, default { 'claude', 'codex', 'opencode', 'pi' }.
                    Foreground command names that make a Block an Agent
                    block, and the agents `a` and `A` offer. An empty list
                    makes both refuse.
    agents.launch   table, default {}. Maps an agent name to the full argv
                    that starts it.

The full setup() call with every default: >lua
    require('rexai').setup({
        refresh_ms = 1000,
        git_refresh_ms = 5000,
        show_exited = true,
        title_width = 40,
        rex_bin = 'rex',
        peek_lines = 20,
        focus_new = true,
        -- nil: the last two directories of the path name a new Session.
        session_name = nil,
        glyphs = {
            needs_input = '!',
            error = 'x',
            done = '+',
            working = '*',
            unreported = '?',
            idle = '-',
            exited = '.',
        },
        agents = {
            apps = { 'claude-code', 'pi' },
            commands = { 'claude', 'codex', 'opencode', 'pi' },
            -- A full argv that replaces { command } for one agent.
            launch = {},
        },
        -- nil: a row stands for the directory of its Block.
        resolve_path = nil,
        -- nil: `o` only says that no review function is set.
        review = nil,
    })
<

==============================================================================
6. HOOKS                                                         *rexai-hooks*

Each hook is a plain function in the config. It is read when it is called,
so a setup() after the Dashboard opened counts.

resolve_path ~
The hook runs for every row of every snapshot, so keep it cheap. It gets a
copy of the row, with block_id, session_id, window_id, harness, label,
status, title and cwd. It returns an absolute directory. A non-empty string
wins. nil or '' keeps row.cwd. The plugin does not expand `~`; use
vim.fn.expand(). The git slot, `o` and `a` all use the directory it
returns. >lua
    require('rexai').setup({
        resolve_path = function(row)
            if row.cwd and row.cwd:find('/scratch$') then
                return vim.fn.expand('~/code/app')
            end
        end,
    })
<
review ~
`o` calls review with the context of the row under the cursor. ctx.path is
always set, because `o` does not call the hook for a row with no directory.
>lua
    require('rexai').setup({
        review = function(ctx)
            -- ctx.path: the directory of the row
            -- ctx.repo_root, ctx.branch: from git, nil when unknown
            -- ctx.session: { id, label }; ctx.window: { id }
            -- ctx.block: a copy of the row
            vim.cmd.tabnew()
            vim.cmd.tcd(vim.fn.fnameescape(ctx.path))
        end,
    })
<
When the hook throws, the Dashboard warns with the error. Without a hook,
`o` says: rexai: no review function is set; add review = function(ctx) ...
end to setup()

session_name ~
`A` asks for a directory and calls session_name with that absolute path,
~ expanded and no trailing slash. The label it returns names the new
Session. `A` looks for a Session with that label first: if one exists, `A`
adds a Window to it. >lua
    require('rexai').setup({
        session_name = function(path)
            return vim.fs.basename(path)
        end,
    })
<
When the hook returns nil or '', the label is the last two directories
joined by `_`: ~/code/app gives code_app. When the hook throws, the
Dashboard warns once with "rexai: session_name failed: ..." and uses that
same rule.

agents.launch ~
launch maps a name from agents.commands to the full argv that starts that
agent. Each element is one argument; no shell parses the list, and Rex starts
it with the login shell's environment. A value that is not a list of strings
is ignored, and the bare name starts the agent. >lua
    require('rexai').setup({
        agents = {
            launch = {
                pi = { 'pi', '--continue' },
            },
        },
    })
<

==============================================================================
7. STARTING AGENT BLOCKS                                      *rexai-starting*

`a` asks for an agent from agents.commands, then for a directory that starts
at the row's directory. It adds a Window to the Session under the cursor.
On the header of the Home session it refuses, because a Window is added
next to an Agent block and the Home session may have none. Use `A` there.

`A` asks for an agent, then for a directory that starts at Neovim's current
directory. It starts a Session labelled by session_name, or adds a Window to
the Session that already has that label.

When agents.commands is empty, both keys warn "rexai: no agent is
configured; set agents.commands in setup()" and open no picker.

With focus_new = true, the plugin selects the new Window or Session after it
is made. With focus_new = false, neither key selects it; the create calls
pass no focus flag.

8. THE REXAI COMMAND                                              *rexai-shim*

bin/rexai puts you in the Dashboard from any shell, inside Rex or outside
it. It finds or creates the Home session, labelled "rexai", with one Window
labelled "dashboard". That Block runs `nvim +Rexai` in your home directory.
It then selects that Window and its Block in the Rex app that owns the
shell, or in the only connected app. Outside Rex, with several apps
connected, it stops with an error. It always returns you to that Session.
Unlike the Dashboard, the shim does not pass `--autostart=false`, so rex may
start a server for it.

    rexai [--name NAME]    --name labels the Session NAME. Default: rexai.
    rexai --help           Print the usage.

Requirements and setup:

- `rex` must be on PATH. The shim ignores rex_bin.
- The nvim that Rex runs must have this plugin installed, because the Block
  runs `nvim +Rexai`.
- Put the shim on PATH with a symbolic link. A copy does not work: the shim
  finds scripts/ beside its own checkout. >sh
    ln -s ~/code/rexai.nvim/bin/rexai ~/.local/bin/rexai
<

9. HEALTH                                                       *rexai-health*

Run |:checkhealth| rexai. It checks, item by item:

- Neovim is 0.11 or newer.
- The rex_bin executable exists.
- The Rex server answers `rex whoami`. If not, it suggests `rex server
  start`.
- The Neovim runs inside Rex ($REX_BLOCK is set). If not, it warns.
- Rex apps are connected. None is an error. Several is a warning when this
  Neovim is not inside one of them.
- git is executable. If not, it warns.
- The rexai shim is on PATH. If not, it warns.

The checks never start a server and never switch your view.

10. HIGHLIGHT GROUPS                                        *rexai-highlights*

Each group is defined with default = true, so a definition that already
exists is kept. Each one links to a Diagnostic or standard group, so a
colorscheme that styles those restyles the Dashboard too.

    RexaiNeedsInput    links to DiagnosticWarn
    RexaiError         links to DiagnosticError
    RexaiDone          links to DiagnosticOk
    RexaiWorking       links to DiagnosticInfo
    RexaiUnreported    links to Comment
    RexaiIdle          links to Comment
    RexaiExited        links to Comment
    RexaiHeader        links to Title
    RexaiDim           links to Comment

==============================================================================
11. LIMITS                                                      *rexai-limits*

- Rex clears the `done` Agent status once you view its Block. The plugin shows
  the status Rex reports and never changes it, so the row shows the new status
  on the next refresh.
- The Dashboard knows only what Rex reports. An agent that reports nothing
  shows as unreported. An agent that no agents.apps or agents.commands
  entry matches is not listed.
- An Exited row appears only for an Agent block the Dashboard saw live in
  this Neovim process. Restarting Neovim forgets them. When Rex no longer
  lists a Block, its row goes too.
- The plugin only reads and selects. It never closes a Block or a Session.

12. DEVELOPMENT                                            *rexai-development*

    just test       Run every plenary spec. The first run clones
                    plenary.nvim into the ignored plenary.nvim/ directory.
    just check      Run stylua --check and lua-language-server. Needs
                    stylua, nvim and lua-language-server on PATH. Outside
                    this recipe, set VIMRUNTIME to your Neovim runtime
                    directory: .luarc.json reads vim.* from
                    ${env:VIMRUNTIME}, so without it your editor's LuaLS
                    reports vim as undefined.
    just format     Format every Lua file with stylua.
    just dev        Run Neovim with this checkout through dev/init.lua.
    just fixture    Record an anonymized fixture from a live Rex. It is the
                    only way fixtures are made.
    just smoke      Check the plugin against the live Rex, by hand. It
                    creates a throwaway rexai-smoke-<hex> Session, never
                    selects or focuses anything, and removes that Session
                    by id. CI has no Rex, so CI never runs it.
